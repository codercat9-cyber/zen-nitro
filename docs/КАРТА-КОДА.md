# ZEN NITRO — карта исходного кода и дорожная карта

Состояние на 31.10.2026, версия **3.7 (код 29)**. Android, Kotlin + Jetpack
Compose + `VpnService`. ~14 000 строк Kotlin, три ядра в отдельных процессах.

Документ из двух частей: **где что лежит и как течёт** (часть 1) и **куда
идём дальше** (часть 2). Простое объяснение «на пальцах» —
[КАК-ЭТО-РАБОТАЕТ-ПРОСТО.md](КАК-ЭТО-РАБОТАЕТ-ПРОСТО.md), зачем это всё и
чем мы отличаемся от других клиентов — [ПОЧЕМУ-ZEN-NITRO.md](ПОЧЕМУ-ZEN-NITRO.md).

## Часть 1. Карта

### 1.1. Слои

```
┌─────────────────────────────────────────────────────────────────────┐
│  ИНТЕРФЕЙС            MainActivity.kt (Compose): экраны, список нод,  │
│                       каскад подключения, сторож, подписки           │
├─────────────────────────────────────────────────────────────────────┤
│  МОЗГИ (core/)        подписки · конфиги · DNS · журнал · проверки   │
│                       Subscriptions, ConfigBuilder, Resolver,         │
│                       Blackbox, LineProbe, WhitelistSniff, NetInfo…   │
├─────────────────────────────────────────────────────────────────────┤
│  СЛУЖБЫ (vpn/)        ZenVpnService — TUN + sing-box (процесс прил.)  │
│                       ZenAwgService — AmneziaWG (:awg / :awg1)       │
│                       DpiService — ByeDPI (:dpi) · ZenTileService     │
├─────────────────────────────────────────────────────────────────────┤
│  ЯДРА (нативные)      libbox.aar (sing-box 1.14.4) · libxrayexec.so   │
│                       (Xray 26.10.10) · libwg.so (AWG v3.1) ·         │
│                       libwg1.so (AWG v1.0.4) · libbyedpi.so           │
└─────────────────────────────────────────────────────────────────────┘
```

Почему ядра в разных процессах: два рантайма Go в одном процессе дерутся
за сигналы и за класс `go.Seq`, а чужой C-код (ByeDPI) при падении унёс бы
туннель с собой.

### 1.3. Как течёт: подключение

```
нажали «Подключиться»
  → MainActivity.toggleConnect: выбор ядра (sing-box / Xray / Amnezia),
    подмена имени для белых списков, разгон Hysteria2
  → ConfigBuilder.build → JSON конфиг
  → ZenVpnService.startVpnBlocking:
       preresolve (адрес ноды через Resolver: DoH ≤ 2,5 с → адрес с диска →
       DNS оператора) → cloudflareSafe → BoxCore (sing-box) [+ XrayEngine]
  → openTun: Android отдаёт TUN, весь трафик телефона идёт в ядро
  → verifyTunnel: «канал живой?» — запрос через туннель
  → сторож в MainActivity ждёт 20 с (XHTTP — 45, белые списки — 40;
    пока ищется адрес — пауза):
       не вышло → откат по ступеням: без подмены имени → без ByeDPI →
       второе ядро → разбор сети (sniffRegime) + проверка линии (LineProbe)
```

Каждая попытка пишется в журнал блоком `┌── … └── ✔/✖`.

### 1.4. Как течёт: подписки

```
loadServers
  → источники: белый список + подписки + свои ссылки
    (одна и та же ссылка — один раз, 3.7)
  → Subscriptions.loadAll: каждую подписку спрашиваем под несколькими
    клиентами, ответы сводим (панели отдают разным клиентам разное)
  → сверка с прошлым списком: «не пришло в выдаче» (gone), переименования,
    переезды на новый IP, «спасение» нод молчавших подписок
  → сведение повторов: внутри подписки, затем зеркала между подписками
    по «паспорту» сервера (3.7); убранные крестиком не возвращаются
  → пинг (не чаще раза в 30 мин; вручную — кнопкой, цифры по ходу)
```

### 1.5. Где менять что

| Хочу… | Иду в… |
|---|---|
| новый протокол / параметр ноды | `Subscriptions.kt` (разбор ссылки) → `model/Node.kt` → `ConfigBuilder.buildOutbound` и `XrayEngine` → `tools/check-configs.sh` |
| поменять маршрутизацию / DNS в туннеле | `ConfigBuilder.kt` (`rules`, `dns`), затем `check-configs.sh` |
| новую ступень отката | сторож в `MainActivity.toggleConnect` (ветки после `waitMs`) |
| новую запись в журнал | `Blackbox.note` / `Blackbox.outcome` |
| новую проверку сети | `LineProbe.kt`, `WhitelistSniff.kt`, `DnsCacheManager.kt` |
| обновить ядро sing-box | `native/sbox/build.sh` (`VER=`), затем новый APK |
| обновить Xray / AmneziaWG без APK | `tools/cores-bot.sh` → проверка на телефоне → `--publish` |

### 1.6. Сборка и проверка

См. [BUILDING.md](../BUILDING.md). Коротко: JDK 17, SDK 34, NDK 25,
`./gradlew assembleRelease`. Ключ подписи — **вне репозитория**
(`keystore.properties`, образец рядом). Любую правку проверять **на
телефоне по журналу**, а не только сборкой и тестами.

## Часть 2. Дорожная карта

### Сделано в 3.7 (31.10.2026)

- Пинг: цифры по ходу замера, прогресс на кнопке, очередь во время подключения.
- Крестик у мёртвых/пропавших нод, «убрать мёртвые» (вторым нажатием), «вернуть убранные».
- Дубли: одна ссылка в двух местах тянется один раз; зеркала сводятся по паспорту сервера.
- IPv6 при «IPv6 off» — мгновенный отказ вместо таймаута через ноду; «IPv6 вкл» больше не ломает сайты без IPv6.
- Адрес ноды: DoH ≤ 2,5 с, затем последний проверенный адрес с диска; сторож не считает время поиска адреса.
- Hysteria2 на сотовой связи без замера скорости — BBR, а не Brutal 100/20.
- Смена LTE ↔ Wi-Fi сбрасывает соединения ядра.
- Журнал пишет ошибки ядра целиком.
- Проверка линии (`LineProbe`) — по кнопке «проверка» без туннеля и сама после провала.
- «Доступно обновление ядер» на главной; робот ядер собирает и зовёт на проверку.
- Модули ядер: опрашиваются все источники, берётся самое свежее (раньше второй источник не работал).
- Канал через ноду жив, а сайты молчат → сразу другая нода, без пустой пересадки на второе ядро;
  плюс замер объёма через туннель: «пришло N КБ, потом тишина» отличает заморозку на линии от глухого выхода.
- «Змея», первый шаг: провалы подряд по оператору — нода с тремя провалами уходит в конец каскада.
- PDP, первый шаг: при почерке «оператор гасит сессию» каскад сам предпочитает TCP-ноды.
- sing-box 1.14.4.

### Сделано в 3.7.1 (01.11.2026) — по живым телефонам Realme и Samsung

- Сторож не крутит нерабочую ноду бесконечно: три возврата подряд с
  «сервер не принимает имя ноды» (x509 / Reality) — остановка и прямой текст
  «подписка устарела — обновите или смените ноду» (было 1989 возвратов за день).
- Подписки при мёртвом туннеле качаются по физической сети — мёртвый туннель
  больше не мешает скачать то, что его починит.
- Заглушки панелей («лимит устройств», «Subscription expired», «подписка
  закончилась») — на заголовке подписки и всплывашкой; «нода» на 0.0.0.0 в
  список не попадает.
- Удаление подписки — по ссылке, а не по номеру строки (снесло соседнюю), и
  её ноды уходят из списка и кеша сразу, не дожидаясь сети.
- «Обновить» во время загрузки не молчит.
- Обновление приложения: сначала напрямую по физической сети, с докачкой с
  места обрыва; при неудаче — «отключите VPN и нажмите ещё раз», причина в журнале.

### Сделано в 3.7.2

- Кольцо говорит правду: «Переподключаюсь…» и «Нет связи» вместо

- Разбор ошибки сертификата — отдельный `CertMismatch` с тестом на строках

- Xray-модули 26.10.31: голый VLESS — на встроенном ядре, остальное — на новом.

### Сделано в 3.7.3 — по живой проверке на Xiaomi 01.11.2026

- Кольцо и при пропаже сети: «Нет сети» (сторож ждёт сеть и туннель не

- Откат набора ядер на сервере одной командой:
  `storage-messenger/tools/rollback-cores.sh` (без аргумента — список бекапов).

### Сделано в 3.7.5 — вылеты, срывы на живых нодах, приёмы Amnezia, ядра «из облака», 06.11.2026

- **Вылет «ending radius must be > 0»** (4 раза за 06.11 на Xiaomi, все — при
  открытии): телефон боком (или маленькое окно) — место под кольцо сжималось
  до нуля, радиус свечения уходил в минус. Воспроизведено поворотом экрана на
  эмуляторе. Теперь кольцо при нулевом месте не рисуется, а главная, когда
  тесно по высоте, прокручивается — кольцо своего размера.
- **Сторож крутил мёртвую ноду шесть часов** (05–06.11: вход NoV лёг целиком,
  3957 попыток подряд, «попытка 0 из 5», журнал провернулся 16 раз). Причины:
  (1) поток возврата обнулял счётчик сразу после того, как вложенный
  reconnect() его прибавил — пауза не росла; (2) служба умела повторять
  только ТУ ЖЕ ноду. Теперь счётчик обнуляет только удача, а служба сама
  уходит на следующую ноду (`core/NodeConfig.kt`: тот же порядок, что у
  каскада; ноды с лёгшего входа — последними; кандидат проверяется мимо
  туннеля — имя разрешается, порт отвечает), если своя не встаёт 30 с и три
  попытки при живой сети. Не больше восьми переходов за обрыв. Приложение
  видит переход сразу (`onNodeSwitch`). Проверено на эмуляторе: свой сервер
  A убит → через 33 с и 3 попытки сторож ушёл на живой B.
- **Мёртвый канал — по времени, а не по числу замеров**: 45 с тишины (на
  медленной сети до 90) и не меньше трёх промахов. Было «5 × терпение»
  двойных замеров — на сотовой связи ~4,5 минуты без связи.
- **«Обрывов оператора: 224 за 10 минут»** — это были наши же неудачные
  попытки вернуться. PdpGuard считает теперь только настоящие обрывы.
- **Hysteria2 — вторым ядром через Xray, с шумом «как у Amnezia»**
  (`core/AwgBait.kt`, `XrayEngine.buildHysteria2`). По журналам 31.10–06.11
  первый подъём на Tele2: AWG 57 %, VLESS 33 %, Hysteria2/TUIC 33 %. AWG берёт
  началом сессии — мусорные пакеты и приманки I1–I5. Xray 26 умеет то же на
  нашей стороне: маска finalmask «noise» с тем же синтаксисом, что I1–I5
  (`<b 0x…>`, `<r N>`, `<rc N>`, `<rd N>`, `<t>`, `<c>`). Перед рукопожатием
  — приманки из AWG-профилей человека (их подобрал провайдер Amnezia, на этом
  операторе они проходят) и три мусорных пакета 40–120 байт, после 30–60 с
  тишины — снова. Salamander и прыжки по портам — тоже масками. Проверено на
  ПК: клиент Hysteria2 из Xray 26.10.10 и 26.10.31 с шумом и Salamander — HTTP
  200 через обычный сервер Hysteria2 (sing-box). Не для нод с «insecure» (в
  Xray 26 нет «не проверять сертификат») и с обфускацией gecko.
- **Ядра — сами, как облачное обновление** (`core/CoreAuto.kt`, решение
  06.11): программа на ПК выкладывает, Zen у людей ставит сам — AmneziaWG на
  любой сети, Xray (~31 МБ) на Wi-Fi; на мобильной — надпись, с первым Wi-Fi
  встанет сам. Проверка — при открытии и после подключения (и у тех, кто не
  открывает приложение неделями), не чаще раза в 3 ч. Снятую версию (автооткат
  или «ВЕРНУТЬ ВСТРОЕННОЕ») сами больше не ставим. Откат на сервере доходит до
  людей сам: версии, которой больше нет в подписанном манифесте нашего
  сервера, Zen снимает.
- **Программа «Zen Ядра» на ПК** (`tools/zen-cores.sh`, ярлык на рабочем
  столе): состояние (апстрим, что раздаётся людям, что собрано, робот),
  «проверить апстрим», «собрать и проверить», «выложить людям», «проверить,
  что сервер отдаёт людям» (публичный манифест, подпись нашим ключом, размер
  каждого файла), «откатить», автоматика (робот по ночам; «выкладывать сам,
  если всё зелёное»). Ночной таймер зовёт `zen-cores.sh auto`.
- **Без Python**: генератор манифеста ядер и три однострочника в скриптах —
  на bash + jq (манифест сверен с прежним — совпадает, кроме даты выпуска).
- Сброс соединения до ноды распознаётся и в строках Xray
  («proxy/vless/outbound … connection refused»), порог — две строки.
- Значок «VLESS-TLS» у ноды без TLS → «VLESS». Вкладки подписаны для
  экранного чтеца («Главная», «Настройки», «Журнал»).
- **Шторка телефона = то, что подключено.** Уведомление обновлялось только
  из цикла замеров, а он стоит, пока туннель поднимается, переподключается или
  сторож меняет ноду, — висели старая нода и старые скорости. Теперь служба
  держит одну строку состояния («Подключаюсь · …», «Подключено»,
  «Переподключаюсь (попытка N)…», «Нет сети — жду», «Канал молчит —
  восстанавливаю») и на любую смену ноды, стадии или «работает/нет» сразу
  перерисовывает уведомление и плитку быстрых настроек: на плитке — имя ноды
  и состояние, «включено» — пока служба на переднем плане (не мигает
  «выключен» во время переподключения). Проверено на Xiaomi по `dumpsys
  notification`: «Подключаюсь… → Проверяю канал → Блокировки пробиты → ↓ ↑ пинг».
- **Экран показывает ту ноду, что в туннеле** (`Prefs.connectedKey`). 06.11
  на главной было «AI🤖», а туннель и шторка — «Lockpick〽»: выбранной ноды
  не оказалось в кэше при запуске, выбор молча упал на первую (её и
  подключили), а ключ выбора остался старым — догрузились подписки, и выбор
  вернулся на AI🤖. Подключение и переход сторожа пишут, какая нода в
  туннеле; пока он жив, выбор восстанавливается по ней. Каскад, короткий
  список в настройках и «найти лучший» теперь меняют ноду как шторка выбора —
  с ключом и с переподключением.
- **Имя ноды за плашкой метки** резалось («Германия_A…») или уезжало на невидимую вторую строку (перенос по
  словам) — от «🇸🇬 Сингапур_AWG 3.0» оставался один флаг. Теперь имя одно на
  всю ширину, плашка — во второй строке, перед протоколом.
- **IP рядом с именем сервера.** Провайдеры перешли с адресов на имена
  (Триллер 06.11: `mos.thriller4ag.com`), и в списке пропали IP. Рядом с
  протоколом, раньше имени — последний проверенный адрес из кеша резолвера (только ответы DoH,
  без сети при отрисовке).

### Сделано в 3.7.4 — Триллер после перенастройки, Xiaomi, Tele2, 04.11.2026

- **Замеры канала внахлёст** (`ZenVpnService.raceDelay`). Через входы
  каскадов часть отдельных соединений виснет на все 15 с («context deadline
  exceeded»), соседние проходят. Замеры шли по одному, первый попадал в
  зависшее, и sing-box «не отзывался за 20 с» — рабочую ноду бросали и
  уходили на Xray. Теперь три замера с шагом в секунду, засчитывается первый
  ответ; так же — YouTube. SPb-AT: было «не отозвался за 20 с», стало
  «канал живой» на 0,9 с.
- **DNS проверяется у DNS туннеля** (`tunnelDns`, clash_api `/dns/query`), а
  не запросом к сайтам, чьё имя разрешает сервер. Было «имена не
  разрешаются» при работающих именах.
- **Reality не «сгорает» от тишины.** Сервер Reality не отвечает на
  приветствие без ключа (пересылает своей маске), и `LineProbe` принимал это
  за «режут TLS к адресу целиком» — нода уходила в конец каскада, хотя в том
  же блоке поднималась. Теперь для Reality это `PARTIAL`, без приговора.
- **Отказ сервера называется отказом** (`core/CoreRefusal.kt`): Hysteria2
  «authentication failed, status code: 404» — «сервер ответил, но не принял
  пароль», а не «молчит или режут»; замеры при этом не ждут впустую.
  Сброс соединения до ноды (три строки «connection refused» на `[proxy]`) —
  «до адрес:порт соединение сбрасывают сразу (RST) — с этой сети к порту
  ноды не пускают». 04.11, Tele2: EKB-FI (5.188.35.157:472) сбрасывали на
  каждом соединении, а с домашнего компьютера тот же порт открыт.
- **Честный итог блока**: «✔ ПОДНЯЛОСЬ · канал есть, но YouTube не ответил»
  вместо «канал проверен» рядом с «не пришло ни байта».
- **Модуль Xray снимается после трёх провалов — по-настоящему.** Удачу
  модулю засчитывал сам запуск процесса (SOCKS открылся), и счётчик
  обнулялся на каждом подъёме — до трёх он не доходил никогда. Теперь
  удача — только проверенный туннель на модуле. 04.11 модуль 26.10.31 пять
  раз подряд не поднял ноды SPb, а встроенный 26.10.10 сразу после — поднял;
  через час те же пять нод встали на модуле за 3–6 с. Дело было во входе
  SPb, который на Tele2 то пускал, то нет, а не в модуле — но счёт должен
  быть честным в обе стороны.
- **Урок Xray — всему входу.** Нода, вставшая только через Xray,
  запоминалась поодиночке, и каждая соседка по входу (у Триллера — десятки
  каскадов на 91.243.86.67) заново теряла 17–20 с на sing-box. Теперь две
  такие соседки по адресу — и остальные идут сразу через Xray.
- **Пускают ли нейросети** (`LocalProbe.ai`): после «🌍 вышла в …» — раз в
  12 ч на ноду — через служебный вход ядра спрашиваем OpenAI и Anthropic API
  без ключа (401 — регион пускают, 403 «страна не поддерживается» — нет) и
  страну, какой нас видит Cloudflare перед chatgpt.com. В журнал:
  «🤖 нейросети через «нода»: ChatGPT ✓ · Claude ✓ · страна для них: CY»;
  в диалоге метки — то же, чтобы «AI» ставили по факту, а не по флагу.
  Проверено: «Россия-Москва» — «ChatGPT ✗ регион · RU».
- **Метки нод**: долгое нажатие в списке — «🤖 AI», «🎬 Видео», «🎮 Игры» или
  своя; плашка в списке и на главной. Хранится по имени ноды
  (`Prefs.nodeLabels`): у каскадов провайдер меняет вход, имя остаётся.

**Живой прогон 04.11, Xiaomi 14, Tele2, все 37 нод ThrillerVPN** (скрипт
выбирает ноду в списке, жмёт «Подключиться» и читает журнал): после правок
поднимаются все 37. NoV, EKB, MOS — sing-box за 3–7 с; входы SPb — через
Xray (урок соседей) за 3–6 с. Часом раньше на Tele2 часть портов не пускала:
EKB:472 — сброс (RST) на каждое соединение, SPb:443 и :452 — «failed to find
an available destination», — при этом с домашнего ПК все порты открыты.
Это линия оператора, не сервер и не клиент; через час прошло само. Нейросети пускают со всех зарубежных
выходов; все четыре «🇺🇸»-каскада выходят через один адрес WARP
104.28.202.100, который сегодня числится Кипром. «🇺🇸 Каскад NoV-US» 03.11
выходил прямо со своего входа в Новосибирске (вход = выход) — сегодня снова
каскад; ему поставлена метка «🤖 AI».

### Дальше — по пунктам обратной связи

**1. Блокировки по отпечатку и поведению (PDP, «подключено, а данные не идут»).**
С середины 2026 ТСПУ режет VLESS+Reality по поведению: отпечаток TLS, число
параллельных соединений, подсеть назначения
([anti-malware.ru, 15.06.2026](https://www.anti-malware.ru/news/2026-06-15-111332/50358)).
План: (а) замер отпечатка, который реально уходит в провод, в журнал;
(б) меньше параллельных соединений — мультиплекс (h2mux/smux у sing-box,
`xmux` у XHTTP) по умолчанию на сотовой связи; (в) по данным `LineProbe`
понять, на каких входах обрыв на ~16–20 КБ, и уводить с них.

**2. Стратегии обхода.** NoDPI ([GVCoder09/NoDPI](https://github.com/GVCoder09/NoDPI))
делает то же, что наш ByeDPI: режет приветствие TLS на части. INCY —
закрытый клиент на Xray-core
([vpnstatus.site](https://vpnstatus.site/clients/incy)); своих новых приёмов
у него нет, всё новое — в самом Xray: движок **Finalmask** (фрагментация,
шум, свои заголовки TCP/UDP, Sudoku)
([Xray-core releases](https://github.com/XTLS/Xray-core/releases/tag/v26.3.27)).
Сделано в 3.7.2: параметр `fm` (Finalmask) разбирается и уходит в Xray.

**3. Дубли подписок и зеркала** — сделано в 3.7, проверить на живых подписках.

**4. Пинг** — сделано в 3.7.

**5. «Змея» — гибкая подстройка под ТСПУ.** Уже есть: память «что
поднималось на этом операторе» (`carrierWins`) и каскад отката. Дальше:
лестница параметров на ноду (отпечаток → фрагментация → мультиплекс → режим
XHTTP → порт), выигрышная комбинация запоминается на пару «оператор + нода»,
при обрыве по почерку `LineProbe` — следующая ступень, а не смена сервера.

**6. Матрёшка и машинный дамп линии.**
(1) искажение входящего канала — Finalmask/шум; (2) снаружи «как все»,
внутри жёстко — VLESS-Reality/XHTTP с CDN снаружи и обфускацией внутри;
(3) **дамп линии** — первая ступень сделана (`LineProbe`, hex первых байт и
килобайты до обрыва). Следующая: кольцевой буфер заголовков пакетов TUN за
последние секунды перед обрывом и выгрузка журнала одной кнопкой. Честные
вердикты «сеть глушат» — только когда и контрольный разрешённый сайт молчит.

**7. Инфраструктура** (по журналу клиента, не по серверам):
вход SPb (91.243.86.67) на LTE — проверить `LineProbe` на Tele2;
Hysteria2 LV на LTE — ниже в приоритете на сотовой связи; CDN-ноды —
в 3.7 адрес берётся с диска, если DoH молчит.

**Xray 26.10.29+ и VLESS без TLS — решено в 3.7.2.** Новое ядро отвергает
VLESS без TLS и без шифрования до публичного IP. Такие ноды `XrayEngine`
(`bareVless`) отдаёт встроенному ядру, всё остальное — модулю; робот проверяет
модуль только на тех конфигах, которые тот и будет крутить

встроенном.
