# ZEN NITRO — карта исходного кода и дорожная карта

Состояние на 31.10.2026, версия **3.7 (код 29)**. Android, Kotlin + Jetpack
Compose + `VpnService`. ~14 000 строк Kotlin, три ядра в отдельных процессах.

Документ из двух частей: **где что лежит и как течёт** (часть 1) и **куда
идём дальше** (часть 2). Простое объяснение «на пальцах» —
[КАК-ЭТО-РАБОТАЕТ-ПРОСТО.md](КАК-ЭТО-РАБОТАЕТ-ПРОСТО.md), зачем это всё и
чем мы отличаемся от других клиентов — [ПОЧЕМУ-ZEN-NITRO.md](ПОЧЕМУ-ZEN-NITRO.md).

## Часть 1. Карта

### 1.1. Слои

```
┌─────────────────────────────────────────────────────────────────────┐
│  ИНТЕРФЕЙС            MainActivity.kt (Compose): экраны, список нод,  │
│                       каскад подключения, сторож, подписки           │
├─────────────────────────────────────────────────────────────────────┤
│  МОЗГИ (core/)        подписки · конфиги · DNS · журнал · проверки   │
│                       Subscriptions, ConfigBuilder, Resolver,         │
│                       Blackbox, LineProbe, WhitelistSniff, NetInfo…   │
├─────────────────────────────────────────────────────────────────────┤
│  СЛУЖБЫ (vpn/)        ZenVpnService — TUN + sing-box (процесс прил.)  │
│                       ZenAwgService — AmneziaWG (:awg / :awg1)       │
│                       DpiService — ByeDPI (:dpi) · ZenTileService     │
├─────────────────────────────────────────────────────────────────────┤
│  ЯДРА (нативные)      libbox.aar (sing-box 1.14.4) · libxrayexec.so   │
│                       (Xray 26.10.10) · libwg.so (AWG v3.1) ·         │
│                       libwg1.so (AWG v1.0.4) · libbyedpi.so           │
└─────────────────────────────────────────────────────────────────────┘
```

Почему ядра в разных процессах: два рантайма Go в одном процессе дерутся
за сигналы и за класс `go.Seq`, а чужой C-код (ByeDPI) при падении унёс бы
туннель с собой.

### 1.3. Как течёт: подключение

```
нажали «Подключиться»
  → MainActivity.toggleConnect: выбор ядра (sing-box / Xray / Amnezia),
    подмена имени для белых списков, разгон Hysteria2
  → ConfigBuilder.build → JSON конфиг
  → ZenVpnService.startVpnBlocking:
       preresolve (адрес ноды через Resolver: DoH ≤ 2,5 с → адрес с диска →
       DNS оператора) → cloudflareSafe → BoxCore (sing-box) [+ XrayEngine]
  → openTun: Android отдаёт TUN, весь трафик телефона идёт в ядро
  → verifyTunnel: «канал живой?» — запрос через туннель
  → сторож в MainActivity ждёт 20 с (XHTTP — 45, белые списки — 40;
    пока ищется адрес — пауза):
       не вышло → откат по ступеням: без подмены имени → без ByeDPI →
       второе ядро → разбор сети (sniffRegime) + проверка линии (LineProbe)
```

Каждая попытка пишется в журнал блоком `┌── … └── ✔/✖`.

### 1.4. Как течёт: подписки

```
loadServers
  → источники: белый список + подписки + свои ссылки
    (одна и та же ссылка — один раз, 3.7)
  → Subscriptions.loadAll: каждую подписку спрашиваем под несколькими
    клиентами, ответы сводим (панели отдают разным клиентам разное)
  → сверка с прошлым списком: «не пришло в выдаче» (gone), переименования,
    переезды на новый IP, «спасение» нод молчавших подписок
  → сведение повторов: внутри подписки, затем зеркала между подписками
    по «паспорту» сервера (3.7); убранные крестиком не возвращаются
  → пинг (не чаще раза в 30 мин; вручную — кнопкой, цифры по ходу)
```

### 1.5. Где менять что

| Хочу… | Иду в… |
|---|---|
| новый протокол / параметр ноды | `Subscriptions.kt` (разбор ссылки) → `model/Node.kt` → `ConfigBuilder.buildOutbound` и `XrayEngine` → `tools/check-configs.sh` |
| поменять маршрутизацию / DNS в туннеле | `ConfigBuilder.kt` (`rules`, `dns`), затем `check-configs.sh` |
| новую ступень отката | сторож в `MainActivity.toggleConnect` (ветки после `waitMs`) |
| новую запись в журнал | `Blackbox.note` / `Blackbox.outcome` |
| новую проверку сети | `LineProbe.kt`, `WhitelistSniff.kt`, `DnsCacheManager.kt` |
| обновить ядро sing-box | `native/sbox/build.sh` (`VER=`), затем новый APK |
| обновить Xray / AmneziaWG без APK | `tools/cores-bot.sh` → проверка на телефоне → `--publish` |

### 1.6. Сборка и проверка

См. [BUILDING.md](../BUILDING.md). Коротко: JDK 17, SDK 34, NDK 25,
`./gradlew assembleRelease`. Ключ подписи — **вне репозитория**
(`keystore.properties`, образец рядом). Любую правку проверять **на
телефоне по журналу**, а не только сборкой и тестами.

## Часть 2. Дорожная карта

### Сделано в 3.7 (31.10.2026)

- Пинг: цифры по ходу замера, прогресс на кнопке, очередь во время подключения.
- Крестик у мёртвых/пропавших нод, «убрать мёртвые» (вторым нажатием), «вернуть убранные».
- Дубли: одна ссылка в двух местах тянется один раз; зеркала сводятся по паспорту сервера.
- IPv6 при «IPv6 off» — мгновенный отказ вместо таймаута через ноду; «IPv6 вкл» больше не ломает сайты без IPv6.
- Адрес ноды: DoH ≤ 2,5 с, затем последний проверенный адрес с диска; сторож не считает время поиска адреса.
- Hysteria2 на сотовой связи без замера скорости — BBR, а не Brutal 100/20.
- Смена LTE ↔ Wi-Fi сбрасывает соединения ядра.
- Журнал пишет ошибки ядра целиком.
- Проверка линии (`LineProbe`) — по кнопке «проверка» без туннеля и сама после провала.
- «Доступно обновление ядер» на главной; робот ядер собирает и зовёт на проверку.
- Модули ядер: опрашиваются все источники, берётся самое свежее (раньше второй источник не работал).
- Канал через ноду жив, а сайты молчат → сразу другая нода, без пустой пересадки на второе ядро;
  плюс замер объёма через туннель: «пришло N КБ, потом тишина» отличает заморозку на линии от глухого выхода.
- «Змея», первый шаг: провалы подряд по оператору — нода с тремя провалами уходит в конец каскада.
- PDP, первый шаг: при почерке «оператор гасит сессию» каскад сам предпочитает TCP-ноды.
- sing-box 1.14.4.

### Сделано в 3.7.1 (01.11.2026) — по живым телефонам Realme и Samsung

- Сторож не крутит нерабочую ноду бесконечно: три возврата подряд с
  «сервер не принимает имя ноды» (x509 / Reality) — остановка и прямой текст
  «подписка устарела — обновите или смените ноду» (было 1989 возвратов за день).
- Подписки при мёртвом туннеле качаются по физической сети — мёртвый туннель
  больше не мешает скачать то, что его починит.
- Заглушки панелей («лимит устройств», «Subscription expired», «подписка
  закончилась») — на заголовке подписки и всплывашкой; «нода» на 0.0.0.0 в
  список не попадает.
- Удаление подписки — по ссылке, а не по номеру строки (снесло соседнюю), и
  её ноды уходят из списка и кеша сразу, не дожидаясь сети.
- «Обновить» во время загрузки не молчит.
- Обновление приложения: сначала напрямую по физической сети, с докачкой с
  места обрыва; при неудаче — «отключите VPN и нажмите ещё раз», причина в журнале.

### Сделано в 3.7.2

- Кольцо говорит правду: «Переподключаюсь…» и «Нет связи» вместо
  «Подключено», когда сторож переподключается или нода не принимает соединение.
- Разбор ошибки сертификата — отдельный `CertMismatch` с тестом на строках
  из настоящих журналов.
- Xray-модули 26.10.31: голый VLESS — на встроенном ядре, остальное — на новом.
- **Finalmask** (Xray 26.3+, п. 2 обратной связи): параметр `fm` в ссылке —
  нарезка приветствия, шум, свои заголовки; нода с маской всегда идёт на Xray.
- Карта для Windows-клиента — [КАРТА-ДЛЯ-WINDOWS.md](КАРТА-ДЛЯ-WINDOWS.md).

### Сделано в 3.7.3 — по живой проверке на Xiaomi 01.11.2026

- Кольцо и при пропаже сети: «Нет сети» (сторож ждёт сеть и туннель не
  трогает) и «Связь пропала…» (сеть есть, канал молчит). Проверка 3.7.2
  показала: 32 с без сети — на кольце «Подключено».
- Откат нового ядра Xray: нода не встала на модуле — та же нода на
  встроенном ядре; встала там — модулю засчитан провал, после трёх модуль
  снимается сам. Вручную — «Вернуть встроенное: Xray» в «Ядрах».
- Откат набора ядер на сервере одной командой:
  `storage-messenger/tools/rollback-cores.sh` (без аргумента — список бекапов).

### Дальше — по пунктам обратной связи

**1. Блокировки по отпечатку и поведению (PDP, «подключено, а данные не идут»).**
С середины 2026 ТСПУ режет VLESS+Reality по поведению: отпечаток TLS, число
параллельных соединений, подсеть назначения
([anti-malware.ru, 15.06.2026](https://www.anti-malware.ru/news/2026-06-15-111332/50358)).
План: (а) замер отпечатка, который реально уходит в провод, в журнал;
(б) меньше параллельных соединений — мультиплекс (h2mux/smux у sing-box,
`xmux` у XHTTP) по умолчанию на сотовой связи; (в) по данным `LineProbe`
понять, на каких входах обрыв на ~16–20 КБ, и уводить с них.

**2. Стратегии обхода.** NoDPI ([GVCoder09/NoDPI](https://github.com/GVCoder09/NoDPI))
делает то же, что наш ByeDPI: режет приветствие TLS на части. INCY —
закрытый клиент на Xray-core
([vpnstatus.site](https://vpnstatus.site/clients/incy)); своих новых приёмов
у него нет, всё новое — в самом Xray: движок **Finalmask** (фрагментация,
шум, свои заголовки TCP/UDP, Sudoku)
([Xray-core releases](https://github.com/XTLS/Xray-core/releases/tag/v26.3.27)).
Сделано в 3.7.2: параметр `fm` (Finalmask) разбирается и уходит в Xray.

**3. Дубли подписок и зеркала** — сделано в 3.7, проверить на живых подписках.

**4. Пинг** — сделано в 3.7.

**5. «Змея» — гибкая подстройка под ТСПУ.** Уже есть: память «что
поднималось на этом операторе» (`carrierWins`) и каскад отката. Дальше:
лестница параметров на ноду (отпечаток → фрагментация → мультиплекс → режим
XHTTP → порт), выигрышная комбинация запоминается на пару «оператор + нода»,
при обрыве по почерку `LineProbe` — следующая ступень, а не смена сервера.

**6. Матрёшка и машинный дамп линии.**
(1) искажение входящего канала — Finalmask/шум; (2) снаружи «как все»,
внутри жёстко — VLESS-Reality/XHTTP с CDN снаружи и обфускацией внутри;
(3) **дамп линии** — первая ступень сделана (`LineProbe`, hex первых байт и
килобайты до обрыва). Следующая: кольцевой буфер заголовков пакетов TUN за
последние секунды перед обрывом и выгрузка журнала одной кнопкой. Честные
вердикты «сеть глушат» — только когда и контрольный разрешённый сайт молчит.

**7. Инфраструктура** (по журналу клиента, не по серверам):
вход SPb (91.243.86.67) на LTE — проверить `LineProbe` на Tele2;
Hysteria2 LV на LTE — ниже в приоритете на сотовой связи; CDN-ноды —
в 3.7 адрес берётся с диска, если DoH молчит.

**Xray 26.10.29+ и VLESS без TLS — решено в 3.7.2.** Новое ядро отвергает
VLESS без TLS и без шифрования до публичного IP. Такие ноды `XrayEngine`
(`bareVless`) отдаёт встроенному ядру, всё остальное — модулю; робот проверяет
модуль только на тех конфигах, которые тот и будет крутить
(`XRAY_MODULE=1` в `check-configs.sh`). Xray 26.10.31: 20 из 20, 4 — на
встроенном.
