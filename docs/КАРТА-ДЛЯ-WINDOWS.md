# ZEN NITRO для Windows — полная карта Android-клиента и план переноса

Снято с Android-версии **3.7.x** (ноябрь 2026). Задача: Windows-клиент,
который **ведёт себя** как Android-версия — с теми же каскадами, проверками
и журналом, — а не только похоже выглядит. Карта кода целиком —
[КАРТА-КОДА.md](КАРТА-КОДА.md); прежний слепок интерфейса (версия 1.6, для
пропорций и характера) — в личных записках `ZEN-NITRO-СЛЕПОК-UI.md`.

---

## 1. Главное решение: на чём писать

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Compose Multiplatform (Desktop, Kotlin/JVM)** — рекомендую | Интерфейс Android уже на Compose: экраны переносятся почти как есть. Вся логика `core/` — обычный Kotlin: подписки, разбор ссылок, сборка конфигов sing-box и Xray, DNS по IP, проверка линии, журнал — **общая с Android, одна кодовая база** | JVM в комплекте (+40–60 МБ после `jlink`); TUN требует прав администратора — отдельная маленькая служба |
| C# / .NET 8 (WPF или WinUI) | Родной вид, небольшой размер | Всю логику — 14 000 строк — переписывать и потом вести две копии; старый `ZenDpiBlaster-Windows` (C#) — заготовка, но на уровне 1.x |

Дальше карта написана так, чтобы годиться для обоих вариантов, но пометки
«общее» означают: при Compose Desktop файл переносится в общий модуль без
переписывания.

## 2. Экраны

### 2.1. Главная (вкладка «домик»)

```

│ [≡ режимы]      ЗАГОЛОВОК      [⟳] [+]        │  TopBar
│                                               │
│               ( ПОДКЛЮЧИТЬСЯ )                │  ConnectRing
│     [🧩 Доступно обновление ядер … ]           │  баннер (если есть)
│     [⬇ Доступно обновление 3.x ]               │  UpdateButton
│        ↓ 0 Б/с   ↑ 0 Б/с   363 мс             │  StatusRow
│              🛡 Режим VPN                      │
│      [🇷🇺 РУ мимо туннеля] [45 прил.]          │  SplitRuChip
├───────────────────────────────────────────────┤
│  🇫🇮 Каскад NoV-FI_AWG 3.0  ⌄                 │  шторка: выбранный сервер
│  Reality-gRPC | 46.8.197.157                   │  → ServerPicker
└───────────────────────────────────────────────┘
   [🏠]            [⚙]            [📄]             нижние вкладки
```

| Элемент | Что делает | Где в коде |
|---|---|---|
| Заголовок | Название + шрифт (готика Pirata One по умолчанию, тап — выбор текста и шрифта) | `TopBar`, `TitleDialog`, `ui/Theme.kt` |
| ≡ «режимы» | Диалог режимов: VPN / DPI-щит / оба | `ModesDialog`, `ModeChips` |
| ⟳ | Обновить подписки | `loadServers()` |
| + | Добавить ссылку или подписку из буфера обмена | «быстрое «+» из буфера» |
| Кольцо | Подключиться / Подключение… / Подключено / **Переподключаюсь…** / **Нет связи** (3.7.2: правда о канале по `Stats.stage`) | `ConnectRing` |
| Скорость, пинг | Живая статистика через управляющий API ядра | `StatusRow`, `core/Stats.kt`, `ClashApi` |
| «РУ мимо туннеля», «N прил.» | Российские сайты и выбранные приложения — напрямую | `SplitRuChip`, `AppPicker`, `core/RuApps.kt` |

### 2.2. Список серверов (шторка)

- Шапка: «Серверы», кнопки-пилюли **пинг** (прогресс «пинг N/M»), **проверка**
  (без туннеля — проверка линии до выбранной ноды), **обновить**.
- Строка: «всего N · показать только рабочие», «✕ убрать мёртвые: N» (второе
  нажатие подтверждает), «вернуть убранные: N».
- Группы-«полки» по подпискам, свёртываются; на заголовке — «живых / всего» и
  **⚠ заглушка панели** («лимит устройств», «Subscription expired»).
- Строка ноды: имя, бейдж протокола · адрес или пометка («нет в свежей
  выдаче», «маскируется под …», «молчит N-й замер»), справа пинг (тильда —
  оценка по соседнему порту) и **✕** у мёртвых.

## 3. Логика: что переносится как есть, а что заменяется

| Модуль Android | На Windows | Пометка |
|---|---|---|
| `Subscriptions`, `XrayConfigParser`, `SingBoxConfigParser`, `AwgParser`, `model/*` | как есть | **общее** |
| `ConfigBuilder`, `SingBoxCompat` | как есть + TUN-вход под Windows (`stack: system`, `auto_route`, `strict_route`) | общее, ветка `platform` |
| `XrayEngine` | Xray — обычный `xray.exe` процессом; SOCKS-цепочка та же | процесс вместо `linker64` |
| `ZenVpnService`, `BoxCore` | sing-box: `libbox` через JNI недоступен — запускать `sing-box.exe run` (или C-shared библиотеку) в **службе с правами администратора**; управление — тот же Clash API | **заменить** |
| `ZenAwgService`, `AmneziaCore` | AmneziaWG для Windows (`amneziawg-windows`, wintun) | **заменить** |
| `ByeDpi`, `DpiService` | `ciadpi.exe` (ByeDPI для Windows) как SOCKS — тот же порт и стратегии; либо zapret `winws` (WinDivert) | процесс |
| `Resolver` (DoH по IP) | как есть; «физическая сеть» — привязка сокета к интерфейсу (`IP_UNICAST_IF`) вместо `Network.socketFactory` | общее + платформенная привязка |
| `LineProbe`, `CertMismatch`, `Cloudflare`, `DnsChoice`, `WhitelistSniff`, `ClashApi`, `LocalProbe` | как есть | **общее** |
| `Blackbox` | как есть, файл в `%LOCALAPPDATA%\ZenNitro\journal\` | общее |
| `Prefs` (SharedPreferences) | JSON-файл настроек | заменить хранилище |
| `CoreModules` | тот же подписанный манифест, ABI `windows-amd64` | общее + новые ABI в `native/modules` |
| `Updater` | скачать подписанный установщик (MSIX/Inno) с докачкой | заменить установку |
| `NetInfo` | тип сети: Ethernet / Wi-Fi / модем; оператор — только у USB-модемов | заменить |
| `RadioKick`, `RadioKeeper`, `PdpGuard` | не нужны на ПК (кроме USB-модемов — позже) | убрать |
| `RuApps` (пакеты `ru.*`) | список российских **процессов** (`*.exe`) + правило `process_name` sing-box | заменить список |
| `ZenTileService` | значок в трее: подключить/отключить, статус | заменить |
| `AppPicker` (исключённые приложения) | выбор `.exe` из запущенных и установленных | заменить источник |

## 4. Потоки, которые обязаны совпасть с Android

1. **Подключение и каскад отката**: снять подмену имени → убрать ByeDPI из
   цепочки → второе ядро (если канал не доказан живым) → другая нода с
   учётом удач и провалов на этой сети → проверка линии. Сторож пауза на
   поиск адреса; три возврата с несовпадением имени — остановка.
2. **Подписки**: несколько «клиентов» на запрос, сведение ответов, одна ссылка
   — один раз, зеркала по паспорту сервера, заглушки панелей — на заголовок,
   при мёртвом туннеле — напрямую.
3. **DNS**: DoH по IP, проверенные адреса нод на диске, проверка подмены.
4. **Журнал**: тот же формат блоков `┌── … └── ✔/✖`, чтобы разбирать одним
   инструментом журналы с обеих платформ.

## 5. План работ

1. **Каркас** (Compose Desktop): общий модуль `core` из Android, окно с тремя
   вкладками, настройки в JSON.
2. **Служба туннеля**: `sing-box.exe` с TUN под администратором, Clash API,
   kill switch через `strict_route`; трей.
3. **Xray и ByeDPI** процессами; **AmneziaWG** для Windows.
4. **Каскад, сторож, проверка линии, журнал** — из общего кода.
5. **Обновления и модули ядер** под Windows; подпись установщика.
6. Сверка поведения на одних и тех же подписках с Android по журналам.
